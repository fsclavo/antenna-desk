# Phase 0 — NEC engine evaluation

**Date:** 2026-10-28  
**Status:** spike complete, decision accepted (ADR-0001)  
**Scope:** evaluate NEC-2 engines for the AntennaDesk MVP on Linux and Windows,
with a license compatible with GPL-3.0-or-later, process or library
integration, portability, available results, and packaging cost. The GUI and
the domain model were not evaluated.

## 1. Candidates

| Candidate | Version evaluated | Language | License | Integration | Maintenance |
|---|---|---|---|---|---|
| **nec2c** (5B4AZ upstream) | 1.3.1 | C | Public domain | CLI / process | Author retired; stable code |
| **nec2c** (KJ7LNW fork) | 1.3.3 (`55be1e0`) | C | GPL-3.0 | CLI / process | Active (2026) |
| **NEC2++ / necpp** | 2.3.4 | C++ | GPL-2.0-or-later | CLI, C++ library, SWIG | Active (2026) |
| **PyNEC** | 2.3.4 | Python + SWIG | GPL-2.0-or-later | In-process Python extension | Active, but no Windows wheels |
| **xnec2c** | 4.4.12 | C + GTK | GPL-3.0 | GUI application | Active; UX reference |
| **Original NEC-2 Fortran** | 1981 | Fortran | Public domain | CLI / process | Historical; requires gfortran |

4nec2, MMANA-GAL, EZNEC, and commercial tools were not evaluated as engines.
MMANA-GAL and the ARRL Antenna Book are reserved as independent cross-check
sources for later phases.

## 2. License and compatibility

AntennaDesk is **GPL-3.0-or-later**. This allows combining the work with
GPLv3-compatible licenses, but **not** with GPL-2.0-only.

| Component | Verified license | Compatible with GPL-3.0-or-later? | Evidence |
|---|---|---|---|
| nec2c upstream 1.3.1 | Public domain | Yes | `README` §7: “nec2c is Public Domain”; Debian copyright |
| nec2c KJ7LNW fork 1.3.3 | GPL-3.0 | Yes | `COPYING` GPLv3; repository metadata |
| NEC2++ 2.3.4 | GPL-2.0-or-later | Yes | Headers: “either version 2 … or (at your option) any later version” |
| PyNEC 2.3.4 | GPL-2.0-or-later | Yes | Derived from NEC2++; same header |
| xnec2c 4.4.12 | GPL-3.0 | Yes | Repository metadata |
| NEC-2 Fortran | Public domain | Yes | US government notice |

**Main risk:** the `nec2c` fork is GPL-3.0 even though the original headers
are public domain. To avoid ambiguity, either use upstream 1.3.1 (public
domain) or the 1.3.3 fork (GPL-3.0). Because AntennaDesk is already GPLv3, the
fork is the practical choice.

**Distribution obligation:** distributing a nec2c binary requires offering the
corresponding source code and license notices. The installer must include
`LICENSE`, the engine's `COPYING`, and the source or a valid source offer. This
must be reviewed by legal counsel before release.

## 3. Integration and results

### nec2c

- Input: NEC-2 deck as text.
- Output: text with sections that are stable within a version.
- Available: input impedance, segment currents, power budget, near field,
  far-field pattern, perfect/finite ground and Sommerfeld ground, frequency
  sweeps.
- Recommended integration: **external process** with `QProcess` or
  `subprocess`/`QThreadPool`.
- Advantages: small binary, no runtime dependencies, crash isolation, easy
  cancellation, compatible license.
- Costs: custom text parser, process management, Windows patch.

### NEC2++ / PyNEC

- NEC2++ provides a C++ API and CLI; PyNEC exposes the API to Python.
- Available: the same NEC-2 results, with structured access.
- Library integration couples the process to the engine; a native failure can
  bring down the application. Process integration preserves isolation but adds
  a heavier C++ dependency.
- PyNEC: convenient for prototypes and validation, but **does not publish
  Windows wheels** for 2.3.4 (only Linux x86-64 and macOS ARM). Packaging it on
  Windows requires a custom SWIG/C++ build.
- Advantage: rich API and active maintenance; useful as a second cross-check
  engine.

### xnec2c

- GTK GUI on top of nec2c. It is not a library.
- Useful as a technical and UX reference; not proposed as a dependency.

## 4. Portability

| Platform | nec2c | NEC2++ | PyNEC |
|---|---|---|---|
| Linux x86-64 | Builds with `cc`; `nec2c` package available | Builds with CMake | Wheel available |
| Windows x86-64 | Requires POSIX patch; builds with MinGW/Zig; PE verified | Official `windows-latest` CI | No wheel; custom build required |
| macOS | Builds with `cc` | CMake | ARM wheel |

The Windows PE was built with Zig 0.13 (clang) and MinGW-w64 GCC 13; both
builds passed the 19 checks under Wine. Native validation runs in GitHub
Actions.

The nec2c Windows patch replaces:

- `sys/times.h` and `times()` with `clock()`.
- `sigaction()` with `signal()`.
- `getopt()` with a minimal parser for `-i`, `-o`, `-h`, and `-v`.

The patch is in `spikes/phase0/patches/nec2c-windows.patch` and is applied
automatically by the Windows build.

## 5. Spike numerical validation

Expected values were transcribed from the **NEC-2 User's Guide, Part III**
(Burke and Poggio), not generated by the engine under test.

| Case | Expected (manual) | nec2c 1.3.3 Linux | nec2c 1.3.3 Windows (Wine) | NEC2++ 2.3.4 | PyNEC 2.3.4 |
|---|---:|---:|---:|---:|---:|
| Example 1, free space, 299.8 MHz | `82.6979 + j46.3060` | `82.6980 + j46.3060` | `82.6980 + j46.3060` | `82.6980 + j46.3060` | `82.6979 + j46.3060` |
| Example 3, perfect ground, 30 MHz | `106.437 + j9.90578` | `106.4400 + j9.9055` | `106.4400 + j9.9055` | `106.4400 + j9.9072` | `106.4415 + j9.9072` |
| Example 3, finite ground, 30 MHz | `111.117 + j11.0075` | `111.1200 + j11.0080` | `111.1200 + j11.0080` | `111.1200 + j11.0090` | `111.1228 + j11.0094` |
| Example 1 scaled to 7.1 MHz | `82.6979 + j46.3060` (±0.1) | `82.6920 + j46.2820` | `82.6920 + j46.2820` | — | — |

Units: ohms. The difference between engines is below `0.02 %` for these
cases. Results are not bit-for-bit identical; therefore the engine and version
must be pinned per simulation.

Smoke test: a 40 m dipole with 21 segments, 21 frequencies, an elevation
pattern, and currents produced 21 impedance blocks, 21 pattern blocks, and 21
current blocks. Runtime: about 6 ms on the test machine.

## 6. Packaging

- **nec2c:** one C executable, no additional runtime. It can be bundled in the
  installer together with its source/notices. Lowest cost.
- **NEC2++:** C++ library and CLI; adds a C++ runtime and increases size.
- **PyNEC:** compiled extension per Python version and platform; without a
  Windows wheel, packaging is the largest risk.
- **xnec2c:** GTK GUI; not applicable.

## 7. Decision matrix

Weighted criteria for the MVP:

| Criterion | Weight | nec2c | NEC2++ | PyNEC |
|---|---:|---:|---:|---:|
| Compatible license | High | Yes | Yes | Yes |
| Linux/Windows portability | High | Yes, small patch | Yes | Windows without wheel |
| Fault isolation | High | Yes (process) | Depends on integration | No (in-process) |
| Available results | High | Yes | Yes | Yes |
| Packaging cost | Medium | Low | Medium | High |
| Maintenance | Medium | Active fork | Active | Active |
| Structured API | Low | No (text) | Yes | Yes |
| Validation maturity | Medium | High (NEC-2) | High (NEC-2) | High (NEC-2) |

## 8. Recommendation

Adopt **nec2c 1.3.3** as the MVP engine, integrated as an **external process**
through a custom adapter. Keep the fork pinned by commit and the Windows patch
in the repository. Use **NEC2++/PyNEC** as a second cross-check engine in
Phase 2, not as a runtime dependency.

Reasons:

1. Compatible license with no practical ambiguity for the GPLv3 project.
2. Small, fast binary with no runtime dependencies.
3. Crash isolation and simple cancellation.
4. Complete NEC-2 results validated against the manual.
5. Windows portability demonstrated with a contained patch.

## 9. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Output format changes between versions | Pin version/commit; parser fixtures and regression tests |
| Windows patch becomes stale | Reproducible build; Windows CI; review on upgrade |
| Long file names in nec2c | Run in a short temporary directory with relative names |
| Incorrect GPL distribution | Include source, COPYING, and notices; legal review |
| Insufficient ground/load validation | Expand reference cases in Phase 2 |
| Fork dependency | Upstream is public domain; revert to 1.3.1 or maintain the patch |
