## Debt closed

### Retired repository name

`persistence/json_repository.py` was a compatibility alias created when the
gzip repository became the ZIP container repository. It had no production
callers, but tests, benchmarks, and the multiband script still imported the old
name. The alias is removed and every caller imports
`ProjectContainerRepository` from `persistence/container.py`. The architecture
and multiband notes now use the canonical name.

### Persistence documentation

The README still advertised "lossless gzip compression" and described the save
limit as compressed JSON; `STATUS.md` still said the PF1 container was schema
60. The README, architecture flow, status, user guide, ADR-0050 schema note, and
multiband performance note now describe the current deterministic ZIP
container, schema 61, per-entry validation, and bounded reads. The radial-screen
wording in the README now says "dense-wire radial-screen approximation", which
matches the exposed feature.

`test_documentation_truth.py` gained a guard that fails if the README,
architecture note, or multiband note reintroduces the retired gzip or
`JsonProjectRepository` wording.

### Live-tuning preview races

The live-tuning dialog now invalidates the in-flight request whenever the
selected dimension, slider value, or pattern option changes. A result from a
superseded target is discarded instead of overwriting the newer label, and the
worker is released so the pending preview can start. Applying or closing the
dialog stops the debounce timer and invalidates any in-flight request, so a
hidden dialog cannot start another solver run.

Two UI tests cover the stale-result guard and the stopped debounce. This is a UI
lifecycle fix only; the solver contract and the preview physics are unchanged.

### Vertical-optimizer droop bound

The vertical descriptor rounded the droop maximum down to a 0.1° step but kept
the unrounded design value as the initial value. A design at the exact
tip-clearance limit could therefore start outside its own search bound and fail
the optimizer's initial-bound invariant. The maximum now includes the initial
value. A registry test constructs a design at `max_radial_droop_deg` and checks
that the initial value lies inside the variable range.

### Development-script coverage

`scripts/benchmark_multiband.py` still imported `far_field_request` from the
pre-extraction `ui.pattern_resolution` module, so the documented benchmark
command failed at import. It now imports `application.pattern_resolution` and
supports `--pattern-frequencies 0`, which the option validation already
allowed. A new `tests/unit/test_scripts.py` imports every development script
under a non-main run name, so stale module paths fail in the normal gate
without executing any CLI. The reduced OCFD benchmark case also completed
against the real solver.
