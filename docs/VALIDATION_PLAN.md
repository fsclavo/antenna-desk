# Validation plan

AntennaDesk distinguishes three levels that must not be confused:

1. **Software tests:** the implementation behaves as specified.
2. **Numerical validation:** results match independent references within
   documented tolerances.
3. **Experimental validation:** results are compared with real measurements,
   accounting for uncertainty and environment.

## Phase 0 — solver spike

Reference values are transcribed from the printed NEC-2 User's Guide
(Burke and Poggio), not generated by the engine under test.

| Example 3, perfect ground, 30 MHz | `106.437 + j9.90578 Ω` | `0.05 Ω` |
| Example 3, finite ground, 30 MHz | `111.117 + j11.0075 Ω` | `0.05 Ω` |

The spike also checks that a 21-frequency sweep produces 21 impedance, pattern,

## Phase 1 — domain and persistence

Phase 1 tests are organized as follows:

- **Unit tests:** units and conversions, geometry, materials, ground models,
  dipole generation, antenna invariants, project invariants, and migrations.
- **Integration tests:** JSON round trips, envelope validation, atomic save
  failure, unknown formats, future schema versions, extra fields, invalid
  geometry, non-finite values, oversized files, invalid JSON, and invalid
  UTF-8.
- **Acceptance tests:** create a dipole from parameters, save, reopen, edit
  the length without mutating the previous snapshot, and open the example
  project.

## Phase 2 — adapter and numerical references

The adapter is tested at three levels:

- **Unit tests:** frequency plans, far-field requests, segmentation,
  input-writer cards, output parsing, SWR, and model fingerprints.
- **Integration tests:** the real nec2c process on Linux and Windows, with
  the solver path supplied by `NEC2C`.
- **Acceptance use case:** `RunSimulation` validates a model/spec pair and
  returns a normalized immutable result.

Reference expectations:

| Case | Expected | Tolerance |
|---|---:|---:|
| Example 1, free space, 299.8 MHz | `82.6979 + j46.3060 Ω` | `0.05 Ω` |
| Example 1 SWR at 50 Ω | `2.351965...` | `0.01` |
| Example 1 maximum power gain | `2.15 dBi` | `0.2 dB` |
| Example 3, perfect ground, 30 MHz | `106.437 + j9.90578 Ω` | `0.05 Ω` |
| Example 3, finite ground, 30 MHz | `111.117 + j11.0075 Ω` | `0.05 Ω` |

The half-wave dipole maximum power gain of approximately `2.15 dBi` is a
standard antenna-theory value. It is used as a sanity check for pattern
parsing and normalization, not as a substitute for impedance validation.

### Segmentation convergence

The NEC-2 User's Guide, Part III, Section II
(<https://www.nec2.org/part_3/secii.html>) recommends segment lengths of at most
`0.1 λ`, `0.05 λ` in critical regions, warns against segments shorter than
`1e-3 λ`, and requires `Δ/a > 8` for less than 1 % error with the thin-wire
kernel.

`tests/integration/simulation/test_segmentation_convergence.py` sweeps 7 to 81
segments on the 30.48 m dipole at 4.8 MHz in free space and at 8 m over finite
ground. It checks numerical stability against the 61-segment solution, not
absolute accuracy. `validate_segmentation` reports
`segmentation.segment_too_long`, `segmentation.segment_too_short`, and
`segmentation.radius_ratio_low` when a model violates the guidelines.

### Two-port math

Feed-line and matching-network algebra is checked against `scikit-rf` 2.2.0, an
independent BSD-3 implementation, in
`tests/unit/domain/test_two_port_skrf.py`. The comparison covers lossless and
lossy lines, L/Pi/T networks, cascades, ABCD order, and transducer gain, with a
`1e-9` relative tolerance. This is an implementation cross-check, not a physical
reference.

### Cross-engine check

The `nec2c` adapter is cross-checked against `nec2++` through PyNEC 2.3.4 for a
free-space dipole, folded dipole, and quad loop. Impedance agrees within `0.1 Ω`
and maximum gain within `0.05 dB`. Both engines use the same thin-wire EFIE
formulation, so this detects implementation and adapter errors, not formulation
errors. Run it with `uv sync --group cross-engine`; the dedicated CI job
installs that optional group.

### Physical invariants

`tests/integration/simulation/test_physical_invariants.py` checks properties
that need no external reference:

- the NEC power budget closes (`P_in = P_rad + P_loss` within 1 %) and the
  reported efficiency matches `100 · P_rad / P_in` within 0.1 percentage points;
- integrating the free-space dipole power pattern over the sphere recovers the
  reported directivity within 0.1 dB;
- rotating the dipole azimuth by 90° rotates the pattern and leaves the maximum
  gain unchanged within 0.05 dB.

A synthetic isotropic pattern integrates to 0 dBi within 0.01 dB as a check on
the integration helper. Reciprocity is omitted because the canonical model has
no two-port antenna representation.

## Template and generator validation

Templates and generators use three evidence levels:

- **Reference-backed:** compared with a traceable independent source using a
  metric-specific tolerance.
- **Published/heuristic:** based on a published design rule or starting point;
  structural and scaling tests are still required.
- **Experimental:** arbitrary or unverified geometry. Structural tests and a
  visible limitation are required; no accuracy claim is made.

The solver adapter remains strictly reference-validated. A missing external
reference does not block an experimental generator. A 10% tolerance is
acceptable for many dimension/heuristic comparisons, but not universally for
gain, nulls, or impedance.

## Future phases

Before adding a new antenna type, it needs:

- A canonical model built from the same domain primitives.
- Unit tests for its domain rules.
- A traceable reference case when an independent numeric oracle exists;
  otherwise evidence level C, a visible warning, and a documented limitation.
- A documented list of limitations.
- Solver adapter integration tests when it becomes simulatable.

Independent sources available for later validation:

- NEC-2 User's Guide examples.
- MMANA-GAL sample models supplied by the project owner.
- The ARRL Antenna Book for published antenna data.

Reference values must be traceable. Do not create expected values with the
same implementation under test. Numerical regression fixtures must include
engine version, configuration, and explicit tolerances.

## ARRL reference checks

The ARRL Antenna Book, 24th edition, Chapter 2 (printed pages 2.12–2.13)
provides two independent properties:

- A 100-foot free-space dipole at 4.8 MHz has 2.14 dBi gain (Figure 2.16).
- An equal-conductor folded dipole has the same gain/pattern as a single-wire
  dipole, with four times the feed-point resistance.
- An equilateral quad loop in free space has approximately 120 Ω radiation
  resistance at resonance (Chapter 5, printed page 5.4).

Tolerances are ±0.15 dB for gain, ±2 Ω for the single-dipole resistance,
±0.5 for the folded/single resistance ratio, and ±15 Ω for the loop resistance. These tests are integration tests
and require `NEC2C`.

## Known limitations

- Relative permeability is not emitted to NEC. Conductor conductivity is
  emitted when `SimulationSpec.include_conductor_losses` is true.
- Far-field samples are NEC power gains in dB. The pattern view can display
  directivity or realized gain by shifting the sampled pattern at its maximum
  direction; the pattern CSV keeps the power-gain columns.
- The end-fed transformer is an ideal impedance ratio, not a physical unun
  model; the counterpoise is simulated as wire geometry, not an ideal ground.
- Series and parallel RLC loads are supported on one segment. L/Pi/T matching
  networks with optional component Q/loss are post-processed before the feed
  line; general transmission-line geometry is not implemented.
- Project files store normalized results and raw solver text; many long runs
  can reach the 32 MB project-size limit.
- Some generated templates remain experimental or heuristic. Folded dipoles
  still lack an independent impedance reference; loops have the ARRL quad-loop
  resistance check. End-fed, J Pole/Slim Jim, Ringo, fan dipole, and vertical
  radial models rely on structural tests and visible warnings.
- VNA CSV import and measurement records are implemented; live instrument
  control is not.
- Optimization covers primary-dimension, multi-element, integer, and Pareto
  searches for generated templates. Custom/imported designs are excluded, and
  there are no boom-length or turning-radius constraints.
- Pattern resolution changes angular sampling only; it does not change NEC
  segment density or solver accuracy.
- Feed-line results are post-processed at the transmitter. The line does not
  alter the simulated antenna currents, pattern, or power gain.
- PySide6 is pinned below 6.10 because 6.12 triggered a shutdown refcount
  crash with pyqtgraph in the test environment.
