# Validation plan

AntennaDesk distinguishes three levels that must not be confused:

1. **Software tests:** the implementation behaves as specified.
2. **Numerical validation:** results match independent references within
   documented tolerances.
3. **Experimental validation:** results are compared with real measurements,
   accounting for uncertainty and environment.

## Phase 0 — solver spike

Reference values are transcribed from the printed NEC-2 User's Guide
(Burke and Poggio), not generated by the engine under test.

| Case | Expected | Tolerance |
|---|---:|---:|
| Example 1, free space, 299.8 MHz | `82.6979 + j46.3060 Ω` | `0.05 Ω` |
| Example 3, perfect ground, 30 MHz | `106.437 + j9.90578 Ω` | `0.05 Ω` |
| Example 3, finite ground, 30 MHz | `111.117 + j11.0075 Ω` | `0.05 Ω` |
| Example 1 scaled to 7.1 MHz | `82.6979 + j46.3060 Ω` | `0.1 Ω` |

The spike also checks that a 21-frequency sweep produces 21 impedance, pattern,
and current sections. Detailed evidence is in
[`spikes/phase0/README.md`](../spikes/phase0/README.md) and the
[engine evaluation](spikes/phase0-solver-evaluation.md).

## Phase 1 — domain and persistence

Phase 1 tests are organized as follows:

- **Unit tests:** units and conversions, geometry, materials, ground models,
  dipole generation, antenna invariants, project invariants, and migrations.
- **Integration tests:** JSON round trips, envelope validation, atomic save
  failure, unknown formats, future schema versions, extra fields, invalid
  geometry, non-finite values, oversized files, invalid JSON, and invalid
  UTF-8.
- **Acceptance tests:** create a dipole from parameters, save, reopen, edit
  the length without mutating the previous snapshot, and open the example
  project.

## Phase 2 — adapter and numerical references

The adapter is tested at three levels:

- **Unit tests:** frequency plans, far-field requests, segmentation,
  input-writer cards, output parsing, SWR, and model fingerprints.
- **Integration tests:** the real nec2c process on Linux and Windows, with
  the solver path supplied by `NEC2C`.
- **Acceptance use case:** `RunSimulation` validates a model/spec pair and
  returns a normalized immutable result.

Reference expectations:

| Case | Expected | Tolerance |
|---|---:|---:|
| Example 1, free space, 299.8 MHz | `82.6979 + j46.3060 Ω` | `0.05 Ω` |
| Example 1 SWR at 50 Ω | `2.351965...` | `0.01` |
| Example 1 maximum power gain | `2.15 dBi` | `0.2 dB` |
| Example 3, perfect ground, 30 MHz | `106.437 + j9.90578 Ω` | `0.05 Ω` |
| Example 3, finite ground, 30 MHz | `111.117 + j11.0075 Ω` | `0.05 Ω` |

The half-wave dipole maximum power gain of approximately `2.15 dBi` is a
standard antenna-theory value. It is used as a sanity check for pattern
parsing and normalization, not as a substitute for impedance validation.

## Phase 3 — guided MVP and GUI

UI tests use `pytest-qt` with the Qt offscreen platform:

- Main window starts with a valid default dipole.
- A simulation runs on a worker thread and populates the results table.
- Saving writes a valid `.antennadesk` file.
- Language switching updates actions.
- Metric/imperial switching preserves the physical length.
- The wizard builds a valid dipole and review page state.

## Phase 4 — comparison and reports

Phase 4 adds tests for:

- Series resonance detection from impedance sweeps, including exact zeros and
  no-crossing cases.
- Adding, renaming, and deleting design variants while preserving at least one.
- Currents tab population and resonance markers in the results view.
- A/B comparison dialog metrics, missing-result handling, SWR overlay, and
  pattern overlay.
- CSV export, SVG chart generation, HTML report rendering, and HTML escaping
  of user-provided text.
- UI wiring for variant actions and CSV/HTML export.

## Phase 5 — optimization and construction

Phase 5 adds tests for:

- Bounded length optimization with synthetic monotonic, non-monotonic,
  no-bracket, max-evaluation, cancellation, and solver-failure evaluators.
- The application use case with an analytical solver, including single-
  frequency/no-pattern evaluation specs and sensitivity probes.
- The optimization dialog worker, evaluation log, sensitivity table, and
  apply-length selection.
- The main-window path that applies the optimized length and runs the full
  simulation.
- Construction-sheet dimensions, simulated-result rows, and HTML escaping.

The suite currently has 227 tests with the solver enabled. The nine solver
integration tests skip when `NEC2C` is not set. All tests run on Python 3.11,
3.12, and 3.13 on Linux and Windows through GitHub Actions. UI tests run
offscreen and do not require a display.

Reproducible adapter check:

```bash
uv run python scripts/run_reference_simulation.py \
  --nec2c spikes/phase0/build/nec2c
```

## Future phases

Before adding a new antenna type, it needs:

- A canonical model built from the same domain primitives.
- Unit tests for its domain rules.
- At least one traceable reference case.
- A documented list of limitations.
- Solver adapter integration tests when it becomes simulatable.

Independent sources available for later validation:

- NEC-2 User's Guide examples.
- MMANA-GAL sample models supplied by the project owner.
- The ARRL Antenna Book for published antenna data.

Reference values must be traceable. Do not create expected values with the
same implementation under test. Numerical regression fixtures must include
engine version, configuration, and explicit tolerances.

## Known limitations

- Relative permeability is not emitted to NEC. Conductor conductivity is
  emitted when `SimulationSpec.include_conductor_losses` is true.
- Far-field values are NEC power gains in dB. Realized gain is not computed.
- No loads, networks, transmission lines, or radial ground screens.
- Simulation results are not persisted in the project file; comparison and
  reports use the current session's cached results.
- The GUI only edits horizontal center-fed dipoles.
- Native PDF export is deferred; HTML reports can be printed to PDF by a
  browser.
- Optimization is limited to a single dipole length and a single reactance
  target; bandwidth, gain, efficiency, and multi-objective optimization are
  not implemented yet.
- PySide6 is pinned below 6.10 because 6.12 triggered a shutdown refcount
  crash with pyqtgraph in the test environment.
